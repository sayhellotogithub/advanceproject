androidx.benchmark

`androidx.benchmark` は、Android アプリケーションの**パフォーマンス測定と最適化**を目的とした Jetpack ライブラリ群です。特に、Android アプリケーションのコードの実行時間を正確に測定し、ボトルネックを特定し、パフォーマンスの回帰 (regressions) を検出するのに役立ちます。

主に以下の2つの主要なモジュールで構成されています。

1. **`benchmark-macro` (マクロベンチマーク)**
   - **用途:** アプリケーション全体の起動時間、UI のスクロールやアニメーションのフレーム落ち (jank)、バックグラウンド処理の実行時間など、**UI やシステム全体のパフォーマンス**を測定します。
   - 特徴:
     - 実際のデバイス上で UI を操作するシナリオをシミュレートし、そのパフォーマンスを測定します。
     - `perfetto` を使用してシステムトレースを収集し、詳細なパフォーマンスデータを提供します。
     - CI/CD パイプラインに統合して、パフォーマンスの回帰を自動的に検出するのに適しています。
   - 典型的な使用例:
     - アプリの起動時間を測定し、改善する。
     - リストのスクロール時のフレームレートを測定し、カクつきを減らす。
     - アニメーションのスムーズさを評価する。
2. **`benchmark-common` / `benchmark-junit4` (マイクロベンチマーク)**
   - **用途:** 特定の関数や小さなコードブロックの実行時間など、**コードの局所的なパフォーマンス**をミリ秒またはナノ秒単位で測定します。
   - 特徴:
     - JVM レベルでコードをウォームアップし、ガベージコレクションの影響を排除するなど、正確な測定のための特別な措置を講じます。
     - JUnit 4 のテストルールとして機能し、通常のユニットテストのように記述できます。
   - 典型的な使用例:
     - データ処理アルゴリズムの効率を比較する。
     - 特定のユーティリティ関数の最適化の効果を検証する。
     - Compose の特定のコンポーザブルの再コンポジションのコストを測定する。

### なぜ重要なのか？

- **客観的な測定:** 「速くなった気がする」ではなく、数値に基づいた客観的なパフォーマンス改善を評価できます。
- **回帰の防止:** 自動化されたベンチマークテストをCIに組み込むことで、コード変更によるパフォーマンスの悪化 (回帰) を早期に発見できます。
- **ボトルネックの特定:** 時間のかかる処理を特定し、最適化の優先順位付けに役立ちます。
- **ユーザー体験の向上:** スムーズでレスポンシブなアプリは、ユーザーにとってより良い体験を提供します。

### 使用方法 (例)

プロジェクトのモジュールレベルの `build.gradle` ファイルに依存関係を追加します。

Gradle

```
// Macrobenchmark の場合
// build.gradle (app/build.gradle または benchmark/build.gradle)
dependencies {
    // AndroidX Benchmark (Macrobenchmark)
    // 最新の安定版を推奨
    androidTestImplementation 'androidx.benchmark:benchmark-macro-junit4:1.2.4' // 2025年5月27日現在の最新安定版
    androidTestImplementation 'androidx.test.ext:junit:1.2.0' // 必要に応じて
    androidTestImplementation 'androidx.test:runner:1.6.0' // 必要に応じて
}

// Microbenchmark の場合
// build.gradle (app/build.gradle の androidTest または test ディレクトリ)
dependencies {
    // AndroidX Benchmark (Microbenchmark)
    // 最新の安定版を推奨
    androidTestImplementation 'androidx.benchmark:benchmark-junit4:1.2.3' // 2025年5月27日現在の最新安定版
}

// Android Studio 向けの設定 (Macrobenchmark でトレースを有効にするため)
android {
    defaultConfig {
        // ...
        testInstrumentationRunner "androidx.benchmark.junit4.AndroidBenchmarkRunner"
    }
    buildTypes {
        release {
            debuggable true // Macrobenchmark を実行するには、リリースビルドタイプをデバッグ可能にする必要があります
        }
    }
}
```

**テストコードの例 (Microbenchmark):**

Kotlin

```
import androidx.benchmark.junit4.BenchmarkRule
import androidx.benchmark.junit4.measureRepeated
import org.junit.Rule
import org.junit.Test

class MyPerformanceBenchmark {

    @get:Rule
    val benchmarkRule = BenchmarkRule()

    @Test
    fun benchmarkMyFunction() {
        benchmarkRule.measureRepeated {
            // ここに測定したいコードブロックを記述
            val result = performSomeCalculation()
            // 必要に応じて結果を使用 (最適化による削除を防ぐため)
            println(result)
        }
    }

    private fun performSomeCalculation(): Int {
        var sum = 0
        for (i in 0..1000) {
            sum += i
        }
        return sum
    }
}
```

### 最新バージョン

Maven Central および Android Developers の公式リリースノートによると、**2025年5月27日**現在、`androidx.benchmark` の主要なモジュールの最新安定バージョンは以下の通りです。

- **`androidx.benchmark:benchmark-macro-junit4`**: `1.2.4`
- **`androidx.benchmark:benchmark-junit4`**: `1.2.3`

これらのライブラリは積極的にメンテナンスされており、Compose UI の登場以降、UI のパフォーマンス測定の重要性が増しているため、その利用価値はさらに高まっています。

### まとめ

`androidx.benchmark` は、Android アプリケーションのパフォーマンスを**客観的に測定し、最適化**するために不可欠なツールです。特に、`benchmark-macro` はアプリ全体の UX を、`benchmark-junit4` は特定のコードの効率を評価するのに役立ちます。パフォーマンスに敏感なアプリケーション開発において、これらのライブラリは非常に重要です。
