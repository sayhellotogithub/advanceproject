javax.inject:javax.inject

`javax.inject:javax.inject` は、**依存性注入 (Dependency Injection: DI)** のための標準的なアノテーション（注釈）とインターフェースを定義する Java 標準ライブラリです。これは、特定の DI フレームワーク（Dagger、Guice、Springなど）に依存せず、DI の基本的な概念を共通の形で表現できるようにするために作成されました。

これは、Java Community Process (JCP) を通じて JSR-330 として標準化された仕様であり、非常に軽量で、特定の DI 実装を含んでいません。その代わりに、DI フレームワークが準拠すべき共通の規約を提供します。

### その役割と重要性

`javax.inject:javax.inject` の主な役割は、DI を使用するアプリケーションにおいて、**フレームワーク非依存の形で依存関係を表現できる**ようにすることです。

主な機能と重要性は以下の通りです。

1. **DI アノテーションの標準化:**
   - **`@Inject`**: コンストラクタ、フィールド、メソッドに適用され、その要素が依存性注入の対象であることを示します。これにより、DI フレームワークは、オブジェクトのインスタンスを作成する際に必要な依存関係を自動的に提供できます。
   - **`@Qualifier`**: 複数の実装がある場合に、特定の依存関係を識別するために使用されるカスタムアノテーションを作成するために使用されます。
   - **`@Named`**: `@Qualifier` の組み込み実装の一つで、文字列名で依存関係を識別するために使用されます（例：`@Named("baseUrl")`）。
   - **`@Singleton`**: オブジェクトがシングルトンとして扱われるべきであることを示します。つまり、アプリケーション内でそのクラスのインスタンスが一つだけ作成され、再利用されるべきであることを示します。
   - **`Provider<T>`**: 型 `T` のインスタンスを遅延的に（必要になったときに）提供するためのインターフェースです。
2. **フレームワークの相互運用性:**
   - この標準が存在することで、開発者は特定の DI フレームワークに強く結合されることなくコードを記述できます。後で DI フレームワークを変更したり、異なるフレームワークを併用したりする場合でも、コードの変更を最小限に抑えることができます。
   - 各 DI フレームワークは、この JSR-330 標準に準拠して実装されているため、`@Inject` などのアノテーションはどのフレームワークを使用しても同じように機能します。
3. **クリーンなコード:**
   - 依存関係を明示的に宣言し、フレームワークがそれらを自動的に注入することで、オブジェクトの生成と依存関係の解決を中央集権的に管理できます。これにより、コードの凝集度が高まり、結合度が低減され、テスト可能性と保守性が向上します。

### `javax.inject:javax.inject` と Dagger/Hilt

Dagger (およびその上に構築された Hilt) は、Android 開発で最も人気のある DI フレームワークの一つです。Dagger は、まさにこの `javax.inject` 標準に準拠して設計・実装されています。

- Dagger/Hilt を使用して ViewModel や他のオブジェクトに依存関係を注入する場合、`@Inject` アノテーションをコンストラクタに付けることが一般的です。これは `javax.inject` ライブラリによって提供されます。
- `@Singleton` や `@Named` といったアノテーションも、`javax.inject` から来ており、Dagger/Hilt で依存関係のスコープや識別を定義するために活用されます。

### `javax.inject:javax.inject` と Jetpack Compose

Jetpack Compose は UI ツールキットであり、直接 `javax.inject` に依存するわけではありません。しかし、Compose アプリケーションが Dagger Hilt などの DI フレームワークを使用する場合、`javax.inject:javax.inject` はその DI フレームワークの基盤として間接的に使用されます。

- Compose の ViewModel を Hilt で注入する場合、その ViewModel のコンストラクタには `@Inject` が付けられ、これは `javax.inject` のアノテーションです。
- Compose アプリの様々なレイヤー（データ層、リポジトリ層など）で依存関係を注入する際に、DI フレームワークと連携するために `javax.inject` のアノテーションが使用されます。

### 最新バージョン

Maven Central によると、**2025年5月27日**現在、`javax.inject:javax.inject` の最新安定バージョンは **`1`** です。このライブラリは JSR-330 の仕様を定義するものであり、その内容は非常に安定しているため、バージョン更新はほとんど行われません。

### 依存関係の追加方法

プロジェクトのモジュールレベルの `build.gradle` ファイルに以下を追加します。通常、Dagger Hilt などを利用する場合に含めます。

Gradle

```
dependencies {
    // 依存性注入の標準アノテーション
    implementation 'javax.inject:javax.inject:1'

    // 他の依存関係 (例: Dagger/Hilt)
    // implementation 'com.google.dagger:hilt-android:<latest_dagger_version>'
    // kapt 'com.google.dagger:hilt-compiler:<latest_dagger_version>'

    // 他の依存関係...
}
```

### まとめ

`javax.inject:javax.inject` は、依存性注入のための標準的なアノテーションとインターフェースを提供する、非常に軽量で基本的な Java ライブラリです。特定の DI フレームワークに依存することなく、DI の概念を共通の形で表現できるため、コードの可搬性と保守性を高めます。Dagger/Hilt のような DI フレームワークの基盤として広く使用されており、Jetpack Compose アプリケーションで DI を利用する場合も不可欠な存在です。
