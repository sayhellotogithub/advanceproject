Androidプロジェクト内で**モジュール間でリソース（資源）名が重複**した場合、**リソース競合が発生する**可能性があり、以下のような挙動・対策があります。

#### 結論から言うと

### マルチモジュール構成では：

- **アプリ（app）モジュールが最終的にどのリソースを参照するかを決定**
- **リソース名が同じ場合、appモジュールに近い依存関係のリソースが勝つ**
- **ビルド時に重複エラーにならない**が、**意図しないリソースが使われる**危険あり

------

## 例：モジュールA と モジュールB の両方に同名リソースがある

```

モジュールA/res/values/strings.xml
<string name="app_name">Module A</string>

モジュールB/res/values/strings.xml
<string name="app_name">Module B</string>
```

そして `app` モジュールで両方を依存していると：

```
dependencies {
    implementation project(":moduleA")
    implementation project(":moduleB")
}
```

### ▶ `R.string.app_name` を使った時、どちらが使われるか？

→ 通常は **最後に読み込まれた方（moduleB）の値が優先**される
 → ただし、GradleやAGPのバージョンにより微妙に挙動が変わることもあります

------

## ❌ 問題点

- **どちらの値が使われるか不透明**
- **ビルドは通るが、意図しないリソースが使われる**
- **アプリ全体の一貫性が崩れる可能性**

------

## ✅ 対策方法（推奨）

### 1. **名前空間（prefix）をつけて区別**

```
<!-- moduleA -->
<string name="modulea_app_name">Module A</string>

<!-- moduleB -->
<string name="moduleb_app_name">Module B</string>
```

### 2. **Baseモジュールや共有モジュールに共通リソースを集約する**

- 共通の `core` モジュールや `designsystem` モジュールを作り、そこに共通の strings, colors, dimensions を置く

### 3. **Composeならコードベースで明示的に扱う**

**Composeでコード内に直接文字列を書く方法（＝ハードコーディング）では、多言語対応（多言語ローカライズ）は困難になります。**

```
val appName = when (BuildConfig.FLAVOR) {
    "a" -> "Module A"
    "b" -> "Module B"
    else -> "Default"
}
```

------

## 🧪 テスト方法

1. `./gradlew :app:assembleDebug` してビルド結果を確認
2. `R.string.app_name` の内容をログや画面表示で確認（意図通りのモジュールから取れているか）

------

## 📝 補足：`mergeResources` タスク

Gradleのビルド過程では各モジュールのリソースが `mergeResources` というフェーズでマージされます。
 この時に **最後にマージされた同名リソースが優先**されるのです。

------

## ✅ まとめ

| 状況                           | 対策                                        |
| ------------------------------ | ------------------------------------------- |
| モジュール間でリソース名が衝突 | `名前空間化` か `共通モジュールに集約`      |
| 重複してもビルドできる         | ただし**意図しない値になる危険あり**        |
| Compose中心なら                | `コードで分岐` や `PreviewParameter` で制御 |
